# 탐색가 서브에이전트 런처

> **전제:** 본 커맨드는 **Claude Code 전용** (CC5W 워크플로우). Agent 도구에 필수 의존.

이 커맨드가 호출되면, 반드시 **Agent 도구**를 사용하여 독립된 서브에이전트를 생성하라.
절대 현재 대화 컨텍스트에서 직접 탐색 작업을 수행하지 마라.

**이유:** 레거시 코드베이스 탐색은 수천 파일·수만 줄 스캔을 수반한다. 메인 `/pm` 세션의 컨텍스트 오염과 토큰 소모를 막기 위해 Agent 격리가 필수다. 또한 `/explorer` 는 **코드 수정 권한이 없다** — 오해를 바탕으로 한 수정을 사전 차단한다.

## 실행 절차

1. 프로젝트 루트의 `CLAUDE.md` 를 읽어 `project_type` 확인 (`legacy` 여야 함). `greenfield` 면 본 커맨드 중단하고 `/analyst` 를 안내.
2. 기존 `CODEBASE_MAP.md` 존재 여부 확인:
   - 없음 → 신규 작성
   - 존재 → "갱신인가 신규 재작성인가" 사용자에게 확인
3. Agent 도구 호출 — 아래 `서브에이전트 프롬프트 템플릿` 사용. `{{CLAUDE_CONTENT}}` · `{{EXISTING_MAP}}` · `{{USER_INPUT}}` 플레이스홀더 치환
4. 서브에이전트 결과를 `CODEBASE_MAP.md` 로 저장 (쓰기는 메인 세션이 수행)
5. 사용자에게 요약 보고 (스캔 파일 수, hotspot 상위 5, 주의 영역 개수)

## 탐색 수칙 (엄격)
1. **쓰기 금지:** Edit/Write 도구 호출 불가. 결과는 메인 세션에 반환하는 텍스트로만 제출.
2. **가정 금지:** 코드가 애매하면 "불확실" 으로 마크. 추측으로 채우지 마라.
3. **우선순위:** 진입점 → 도메인 핵심 → 외부 경계 → 유틸 순으로 탐색.
4. **시간/토큰 경계:** 초기 1회 스캔은 파일 수 상위 100개로 제한. 추가 스캔은 사용자 승인 후.
5. **객관성:** 개발자 의도가 아닌 코드의 실제 동작과 구조만 기술.

## 수행 절차
1. **파일 트리 스캔** — 디렉토리별 의미 추정 (src/domain/infra/test 등)
2. **진입점 식별** — main, index, controllers, Startup, Program, service entry 등
3. **외부 의존** — DB 클라이언트·HTTP SDK·파일 I/O·메시지 브로커·OS API
4. **Git blame hotspot** — 최근 6개월 수정 빈도 상위 N파일. (Git 이력 없으면 스킵하고 별도 기재)
5. **기존 테스트 평가** — 단위/통합 비율, 테스트 프레임워크, 커버리지 추정, 신뢰도 (낮음/보통/높음) + 근거
6. **"안전 영역 vs 주의 영역" 맵** — 자주 변경 · 테스트 없음 · 진입점 인접 3 조건 교차
7. **산출** — 아래 출력 서식을 그대로 채워 반환
