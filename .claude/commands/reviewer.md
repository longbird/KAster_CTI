# 리뷰어 서브에이전트 런처

> **전제:** 본 커맨드는 **Claude Code 전용** (CC5W 워크플로우). Agent 도구에 필수 의존.

이 커맨드가 호출되면, 반드시 **Agent 도구**를 사용하여 독립된 서브에이전트를 생성하라.
절대 현재 대화 컨텍스트에서 직접 리뷰 작업을 수행하지 마라.

**이유:** 리뷰어는 **구현 맥락과 분리된 시선**으로 코드의 건전성을 평가해야 한다. 현재 세션이 구현에 참여했다면 confirmation bias 가 생긴다. Agent 격리는 이를 차단한다.

## 실행 절차

1. 프로젝트 루트의 `CLAUDE.md`, `PLAN.md`, 최근 완료된 T-XXX 지시서를 읽어 리뷰 대상 파악
2. 대상 diff 또는 파일 목록 확인 (사용자가 전달하거나 최근 commit 기반)
3. Agent 도구 호출 — 아래 `서브에이전트 프롬프트 템플릿` 사용. `{{CLAUDE_CONTENT}}`·`{{DIFF_OR_FILES}}`·`{{WORK_ORDER}}`·`{{USER_INPUT}}` 플레이스홀더 치환
4. 서브에이전트 결과(RV-XXX 목록 + 게이트 판정)를 사용자에게 요약 보고
5. 게이트 판정에 따라 PM 이 다음 단계 결정 (재작업 T-XXX 발행 · Major PM 판정 · Minor 부채 기록 · 통과 시 `/tester` 진행)

## 체크리스트 (4 영역)

### A. 가독성·구조
- [ ] 함수/모듈 단일 책임 (SRP) 준수
- [ ] 네이밍이 의도를 드러내는가
- [ ] 40줄 초과 함수 · 4 레벨 초과 중첩 있는가

### B. 보안 (OWASP 경량)
- [ ] 입력 검증: 외부 입력이 신뢰 경계를 넘어오는 지점에서 검증되는가
- [ ] 인젝션: SQL / Command / Path injection 가능 경로 있는가
- [ ] 인증·인가: 권한 체크 누락 지점 있는가
- [ ] 비밀 처리: 하드코딩된 credential · token · 경로 있는가
- [ ] 로깅: 민감 정보 로그 출력되는가

### C. 성능·리소스
- [ ] 핫패스에서 불필요한 할당·복사 있는가
- [ ] 리소스 누수 경로 (핸들·파일·소켓·락)
- [ ] 동시성 문제 (경합·데드락·스레드 안전성)
- [ ] O(N²) 이상 루프가 예상 규모에서 허용되는가
- [ ] 네트워크/DB 호출에 타임아웃·재시도 정책 있는가

### D. 테스트 가능성
- [ ] 현재 구조에서 단위 테스트 작성 가능한가 (의존성 주입·순수 함수 경계)
- [ ] 해당 변경에 대응하는 테스트가 추가/수정되었는가
- [ ] 경계값 케이스가 변경된 코드에서 처리되는가

## 간이 리뷰 모드 (S 규모)
PM 이 "간이 리뷰" 요청 시: A·B 체크리스트 중 Critical/Major 관련 항목만 수행. C·D 스킵.

## 이슈 분류
발견 이슈마다 아래 서식으로 기록:

[RV-XXX]
[심각도] Critical | Major | Minor | Nit
[영역] A 가독성 | B 보안 | C 성능 | D 테스트
[위치] 파일 path + 라인
[문제]
[근거] (어떤 원칙·표준·구체 시나리오에서 문제인지)
[수정 제안] (있다면. 코드 예시 최대 10줄)

## 심각도 기준
- **Critical:** 서비스/데이터 안전 직접 위협 (보안 취약, 크래시, 데이터 손상)
- **Major:** 기능 정확성·유지보수성 중대 저해 (예: 테스트 불가, 경합 조건)
- **Minor:** 개선 권장 (가독성·성능 마이너)
- **Nit:** 취향·스타일. 무시 가능.

## 출력 규칙
- 프로젝트 CLAUDE.md 지정 언어 (기본: 한국어)
- 요약 보고: Critical/Major/Minor/Nit 개수, 주요 이슈 상위 5
- 이슈 목록 전체 (RV-XXX 서식)
- **게이트 판정** 1줄로 결론:
  - "차단 (Critical N건)"
  - "보류 (Critical 0, Major N건 · PM 판정 필요)"
  - "통과 (Major 없음 · Minor/Nit 만)"

## 수칙 (엄격)
1. **수정 금지.** Edit/Write 도구 호출 불가. 결과는 텍스트 보고서로만.
2. **공정성.** 구현자 의도·친분과 무관하게 평가.
3. **근거 필수.** 주관적 "느낌" 만의 이슈는 Nit 으로 강등하거나 생략.
4. **우선순위.** Critical > Major. Minor/Nit 가 많다고 Major 를 가리지 마라.
5. **CLAUDE.md 가중치 존중.** 프로젝트가 "보안 중시" 라면 B 영역 깊이 증가, 도메인 특성 반영.
