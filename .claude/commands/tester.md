# 테스터 서브에이전트 런처

> **전제:** 본 커맨드는 **Claude Code 전용** (CC5W 워크플로우). Agent 도구에 필수 의존.

이 커맨드가 호출되면, 반드시 **Agent 도구**를 사용하여 독립된 서브에이전트를 생성하라.
절대 현재 대화 컨텍스트에서 직접 테스트 작업을 수행하지 마라.

**이유:** 테스터는 **구현 맥락을 모르는 상태에서** 명세(PLAN.md / BUSINESS_FLOW.md / REQUIREMENTS.md)와 실제 코드만으로 객관적 검증을 해야 한다. 현재 세션이 구현에 참여했다면 편향이 생긴다.

## 실행 절차

1. 프로젝트 루트의 `CLAUDE.md`, `PLAN.md`, `BUSINESS_FLOW.md`, `REQUIREMENTS.md` 를 읽어 현재 상태·테스트 대상을 파악
2. 테스트 대상 소스 파일 목록 파악 (PLAN.md §3 에서 최근 완료된 T-XXX 로부터)
3. Agent 도구 호출 — 아래 `서브에이전트 프롬프트 템플릿` 사용. `{{PLAN_CONTENT}}`·`{{TARGET_FILES}}`·`{{USER_INPUT}}` 플레이스홀더 치환
4. 서브에이전트 결과를 사용자에게 요약 보고

## 테스트 수칙

### 설계 원칙
1. **명세 기반**: 정상/대안/예외 흐름 각각에 대해 테스트 케이스 도출
2. **경계값 분석**: 빈 값, 0, 최대 길이, 특수문자 등 경계 조건 반드시 포함
3. **실패 시나리오 우선**: 정상보다 실패/예외 케이스를 더 많이 작성
   - 리소스 없음 / 권한 없음
   - 외부 의존성 단절 (네트워크·DB·파일시스템)
   - 동시성 문제 (경합, 타임아웃, 중도 취소)
   - 잘못된 입력 (malformed, out-of-range, injection)
4. **독립성**: 각 테스트는 독립 실행 가능. 순서 의존 금지.
5. **재현 가능성**: fixture 설정·정리 명확히

### 케이스 서식
[TC-XXX] 테스트 케이스 ID
[분류] 단위 | 통합 | 시스템
[대상 모듈] MOD-XXX
[대상 흐름] BF-XXX
[시나리오]
[사전 조건]
[실행 단계] 1. 2. ...
[기대 결과]
[정리]

### 테스트 코드 규칙
- 함수명: test_<대상>_<시나리오>_<기대결과>
- AAA (Arrange-Act-Assert) 엄수
- 매직 넘버 금지 — 명명된 상수 사용
- 테스트 코드에도 프로덕션 코드와 동일한 품질 기준

## 작업 프로세스
1. 명세에서 테스트 대상 식별
2. 대상 소스를 읽어 테스트 가능한 인터페이스 파악
3. 테스트 케이스 설계서 작성
4. tests/ 디렉토리에 테스트 코드 구현
5. 결함 발견 시 아래 서식으로 보고:

   [BUG-XXX]
   [심각도] Critical | Major | Minor
   [재현 경로] 단계별
   [기대 동작] vs [실제 동작]
   [관련 모듈] MOD-XXX
