KAster_CTI 관리자 웹 디자인 시안

요약: 기본 추천은 시안 A: 운영상황실형 콘솔입니다. 현재 관리자 앱의 다크 톤, KPI 스트립, 콜 칸반, 경보 패널 구조를 유지하면서 정보 밀도와 상태 신호를 정리하는 방식이 가장 현실적입니다.

Lazyweb MCP 도구가 현재 세션에 노출되지 않아 공개 웹 레퍼런스 캡처와 현재 앱 구조 분석을 기준으로 작성했습니다.

1순위 시안 A: 운영상황실형

실시간 콜센터 관제에 최적화합니다. KPI, 경보, 콜 칸반, 큐/상담원 상태를 한 화면에서 스캔하게 합니다.

적합 화면: Dashboard, Live Calls, Monitoring

난이도: 낮음-중간

병행 적용 시안 B: 데이터 워크벤치형

테이블, 필터, 상세 drawer, 일괄 액션을 중심으로 고객/차단/녹취/리포트 업무를 빠르게 처리합니다.

적합 화면: Customers, Blocklist, Reports, Recordings

난이도: 중간

단계 적용 시안 C: 지점 운영 포털형

지점, 권한, PBX/IVR 설정처럼 변경 위험이 있는 영역을 검증/미리보기/적용 흐름으로 묶습니다.

적합 화면: Branches, Permissions, Asterisk, System

난이도: 중간-높음

Recommendations / Next Steps

  1. 기본안은 시안 A로 선택 — 운영자는 현재 상태, 경보, 병목을 빠르게 봐야 하므로 관제형 대시보드가 맞습니다.
  2. 고객/차단/녹취/리포트 화면은 시안 B 패턴을 부분 적용 — 조회, 비교, 편집, 내보내기 흐름이 핵심입니다.
  3. 멀티 지점/설정 운영이 커지면 시안 C를 단계적으로 적용 — 위험 설정은 변경 전후와 검증 상태를 함께 보여줘야 합니다.

시안 A: 운영상황실형 콘솔

용도: 대시보드, 실시간 콜, 모니터링. 핵심: 지금 어디가 막혔는지 5초 안에 보여야 합니다.

┌────────────────────────────────────────────────────────────────────┐
│ CTI Admin  지점: 전체  갱신 23:32:10  API OK  AMI OK  Redis OK      │
├───────────────┬────────────────────────────────────────────────────┤
│ 운영 메뉴      │ KPI strip: 대기 | 응답률 | 평균대기 | 포기 | 상담중    │
│               ├────────────────────────────────────────────────────┤
│ Dashboard     │ 경보 3건     │ 실시간 콜 칸반: 대기/벨/통화/후처리/종료 │
│ Live Calls    │              │                                    │
│ Monitoring    ├──────────────┴────────────────────────────────────┤
│ Reports       │ 큐 요약 테이블 │ 상담원 상태 │ 시간대 트래픽           │
└───────────────┴────────────────────────────────────────────────────┘
  • 상단 카드형 헤더를 줄이고 지점, 갱신시간, 인프라 상태를 한 줄 운영 바에 고정합니다.
  • KPI는 카드보다 구분선으로 나뉜 strip이 적합합니다.
  • 콜 칸반 카드에는 ANI, DID, 큐, 경과시간만 남깁니다.
  • 경보는 색보다 심각도, 발생시각, 대상 큐, 조치 버튼이 먼저 읽히게 합니다.

시안 B: 데이터 워크벤치형 관리자

용도: 고객, 차단목록, 녹취, 리포트, 상담원/큐 설정. 핵심: 검색, 비교, 편집, 내보내기가 한 흐름 안에서 끝나야 합니다.

┌────────────────────────────────────────────────────────────────────┐
│ 고객 관리                         [지점] [상태] [검색어] [가져오기] │
├───────────────┬────────────────────────────────────────────────────┤
│ 업무 메뉴      │ Saved filters | 빠른 필터 칩 | 선택 12건: [차단] [SMS] │
│               ├────────────────────────────────────────────────────┤
│ Customers     │ 고객명 │ 대표번호 │ 지점 │ 최근통화 │ 수신거부 │ 메모 │
│ Blocklist     │ ...    │ ...      │ ...  │ ...      │ ...      │ ...  │
│ Recordings    ├────────────────────────────────────────────────────┤
│ Reports       │ 우측 drawer: 고객 상세, 통화 이력, 메모, 인라인 편집    │
└───────────────┴────────────────────────────────────────────────────┘
  • 상단에는 설명문보다 필터, 검색, 가져오기/내보내기, 선택 항목 액션을 둡니다.
  • 상세는 새 화면보다 drawer를 유지합니다.
  • 운영 판단 필드만 기본 노출하고 나머지는 상세 drawer로 보냅니다.

시안 C: 지점 운영 포털형

용도: 지점, 권한, PBX/IVR, 번호, 시스템 설정. 핵심: 어느 지점의 어떤 설정이 운영 반영 가능한 상태인지 보여야 합니다.

┌────────────────────────────────────────────────────────────────────┐
│ 설정 관리  지점: 강남  배포상태: 검증필요  [미리보기] [검증] [적용] │
├───────────────┬────────────────────────────────────────────────────┤
│ 설정 메뉴      │ Branch summary: DID 12 | 큐 4 | 상담원 38 | 프롬프트 9 │
│               ├───────────────────────┬────────────────────────────┤
│ Branches      │ 설정 섹션 목록         │ 선택 섹션 편집 폼            │
│ Prompts       │ DID / IVR / Trunk      │ 변경 전후 diff / preview      │
│ Permissions   │ Queue / Forwarding     │ 검증 결과 / 운영 반영 로그     │
└───────────────┴───────────────────────┴────────────────────────────┘
  • 설정 화면은 좌측 섹션 목록과 우측 편집/미리보기 구조가 좋습니다.
  • PBX/IVR/Trunk 설정에는 변경 전후 diff, 검증, 적용 버튼을 같은 작업줄에 둡니다.
  • 성공/실패 결과는 모달보다 페이지 안의 검증 패널에 남깁니다.

최종 추천 조합

A를 전체 시각 언어의 기준으로 삼고, B와 C를 화면 성격별 패턴으로 섞는 하이브리드가 가장 적합합니다.

  • 시안 A: /dashboard, /live-calls, /monitoring
  • 시안 B: /customers, /blocklist, /reports/*, /agents, /queues
  • 시안 C: /settings/branches, /settings/permissions, /asterisk, /numbers, /system
