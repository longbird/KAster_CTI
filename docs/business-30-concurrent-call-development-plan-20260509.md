# CTI 솔루션 상용화 요약 제안서

작성일: 2026-05-09

## 1. 제안 목적

현재 개발 중인 CTI 솔루션은 PBX 서버, CTI 서버, 상담원 화면, 관리자 화면, Windows 상담원 앱, 테스트 도구까지 기본 구조와 핵심 기능이 상당 부분 구현된 상태다. 다만 이는 상용 납품 완료 상태가 아니라, **1차 기반 개발이 끝나고 운영 상품화에 필요한 추가 개발이 남아 있는 단계**다.

이번 추가 개발의 목적은 신규 개발을 다시 시작하는 것이 아니라, 현재 구현된 시스템을 **30동시통화 기준으로 실제 사업 제안과 납품이 가능한 상용 수준**으로 마무리하는 것이다.

## 2. 현재까지 진행된 내용

현재까지 확보된 주요 산출물은 다음과 같다.

| 구분 | 진행 내용 |
| --- | --- |
| PBX 연동 | 인입, 발신, 큐, 전환, 녹취, IVR, 설정 반영 구조 구현 |
| CTI 서버 | 통화 이벤트 수집, 통화 상태 조립, REST API, 실시간 이벤트, 인증/권한 구현 |
| 상담원 화면 | 로그인, 상태 변경, 현재 통화, 공지, 기본 통화 제어 구현 |
| 관리자 화면 | 지사, DID, 큐, 상담원, 권한, 발신번호, 녹취, 리포트, 모니터링 구현 |
| Windows 상담원 앱 | 소프트폰 등록, 통화 제어, 트레이, 자동 업데이트, 패키징 기반 구현 |
| 테스트 도구 | PBX 인입 테스트, WebSocket 확인, DB/로그 증적 수집, PASS/FAIL 리포트 구현 |

이미 리허설 환경에서 PBX smoke gate, 서버 빌드, 관리자 화면 빌드, 데스크톱 앱 테스트와 패키징 검증까지 진행된 상태다. 다만 이 결과는 기반 기능의 동작 확인이며, 실제 30동시통화 상용 운영을 위해서는 아래 추가 개발과 현장 검증이 더 필요하다.

## 3. 남은 핵심 과제

상용 납품을 위해 남은 과제는 **추가 개발**과 **운영 검증**으로 나누어 봐야 한다. 현재 상태는 개발이 모두 끝난 것이 아니라, 핵심 기반 위에 실제 납품에 필요한 업무 기능과 운영 안정화 기능을 추가로 완성해야 하는 단계다.

1. 상담원 업무 기능 추가 개발
   - 통화 중 고객 정보, 이전 통화 이력, 메모 입력, 안내 문구, 큐 현황을 한 화면에서 볼 수 있게 보강한다.
   - 전환 단축키, 자동응답/거절 정책, 상담원 상태 변경 사유 등 실제 상담 업무에 필요한 기능을 추가한다.

2. 관리자 운영 기능 추가 개발
   - 30동시통화 운영에 필요한 모니터링 화면과 알림 기준을 보강한다.
   - 장애 이력, 통화 누락 확인, 운영 리포트, 설정 변경 검증 화면을 상용 운영 기준으로 정리한다.

3. PBX 연동 안정화 개발
   - 인입, 발신, 큐, 전환, 녹취, IVR 흐름에서 상태 누락이나 중복 이벤트가 없도록 보강한다.
   - PBX 설정 반영, 검증, rollback 절차를 시스템 기능과 운영 절차로 연결한다.

4. 30동시통화 검증 도구 및 시나리오 보강
   - 1건 smoke call부터 30동시통화까지 단계별 테스트 시나리오를 정리한다.
   - 통화 상태, 녹취, 통화 이력, 실시간 이벤트 누락 여부를 자동으로 확인할 수 있게 보강한다.

5. 운영 배포 절차 확정
   - 운영 서버, 도메인, DB, Redis, PBX 접속 정보를 기준으로 배포 절차를 고정한다.
   - 배포 실패 시 rollback 기준을 문서화한다.

6. 실제 상담원 PC 검증
   - Windows PC, 헤드셋, 현장 네트워크에서 수신, 발신, 전환, 종료, 오디오 장치를 확인한다.
   - 웹 화면과 데스크톱 앱이 같은 통화 상태를 보는지 확인한다.

7. 장애 알림과 운영 모니터링
   - PBX 연결 끊김, DB/Redis 장애, 실시간 이벤트 지연, 미처리 이벤트 증가를 감지한다.
   - 관리자 화면과 외부 알림 채널을 연결한다.

8. 운영 문서와 인수 자료 작성
   - 설치, 배포, 장애 대응, 백업, 데이터 보존, 테스트 결과를 인수 문서로 정리한다.

## 4. 일정 및 비용

예상 일정은 **최소 4개월**이다.

30동시통화 CTI 솔루션은 단순 화면 개발이 아니라 PBX 연동, 상담원 업무 흐름, 관리자 운영 설정, 실제 PC 검증, 장애 대응, 운영 문서까지 함께 맞춰야 한다. 따라서 최소 4개월을 기준으로 개발과 검증 일정을 잡는 것이 현실적이다.

| 단계 | 내용 |
| --- | --- |
| 1개월차 | 추가 개발 범위 확정, 상담원/관리자 화면 보강, 운영 배포 기준 정리 |
| 2개월차 | PBX 연동 보강, 30동시통화 테스트 시나리오 작성, 장애 감지 기준 정리 |
| 3개월차 | 실제 상담원 PC/헤드셋/네트워크 검증, 부하 테스트, 병목 보정 |
| 4개월차 | 최종 리허설, 운영 문서, 인수 자료, 납품 검증 리포트 작성 |

추가 개발 및 상용화 마무리 비용은 **약 2,000만원**으로 산정한다.

이 금액의 대부분은 추가 개발에 필요한 비용이다. 주요 범위는 상담원 업무 화면 보강, PBX 연동 안정화, 30동시통화 검증 도구/시나리오 보강, 장애 감지 기준 정리, 관리자 운영 기능 보완이다.

실제 환경 적용에 필요한 비용은 상대적으로 작게 산정한다. 운영 서버 값 반영, 현장 PC 설치 확인, 배포 설정 조정, 기본 smoke test 등은 추가 개발비 안에서 최소 범위로 처리한다. 단, 서버 장비, 통신 회선, 도메인, 인증서, 녹취 저장소, 외부 알림 발송 요금 등 외부 인프라 비용은 별도다.

최종 리허설 이후에는 **2개월간 모니터링 및 추가 개선 작업**을 별도 운영 지원 범위로 둔다. 이 기간에는 실제 사용 중 발생하는 오류, 상담원 피드백, 통화 상태 누락, 화면 불편 사항, 운영 리포트 보완을 대응한다.

- 최종 리허설 이후 운영 지원 기간: 2개월
- 운영 지원 및 추가 개선 비용: 월 **약 200만원**
- 2개월 기준 별도 비용: 총 **약 400만원**

## 5. 사업자 설득 포인트

현재 시스템은 기획 단계가 아니라 실제 구현과 리허설 검증이 진행된 상태다. 다만 상용 납품에 필요한 상담원 업무 기능, 운영 모니터링, PBX 안정화, 30동시통화 검증 기능은 아직 추가 개발이 필요하다. 따라서 추가 투입 비용은 이미 만들어진 기반 위에 상용 상품으로 필요한 기능을 완성하는 비용이다.

30동시통화는 중소형 콜센터나 지사형 운영사에 제안하기 좋은 현실적인 1차 목표다. 이 기준에서 안정성을 증명하면 이후 50호, 100호 이상 확장도 같은 검증 체계를 확장하는 방식으로 진행할 수 있다.

사업자는 이 솔루션을 단순 전화 시스템이 아니라 다음 가치를 가진 운영형 CTI 시스템으로 제안할 수 있다.

- 상담원 상태와 통화 상태 실시간 관리
- 통화 이력, 녹취, 메모, 리포트 통합
- 지사/상담원/권한/발신번호 운영 관리
- 장애 감지와 운영 모니터링
- Windows 상담원 앱과 웹/관리자 화면 연동
- PBX 인입 및 부하 검증 도구 기반 납품 검증

## 6. 사업자 확인 필요 사항

진행 전 사업자가 확정해야 할 사항은 다음과 같다.

| 항목 | 확인 내용 |
| --- | --- |
| 운영 환경 | 서버 위치, 도메인, 인증서, 운영 DB |
| 통신 환경 | DID, SIP trunk, 내선, 동시 통화 계약 |
| 상담원 장비 | 실제 Windows PC, 헤드셋, 네트워크 |
| 알림 채널 | 장애 알림을 받을 방식 |
| 데이터 정책 | 녹취, 로그, 감사 이력 보관 기간 |

## 7. 결론

현재 개발 상태를 기준으로 볼 때, 약 2,000만원을 추가 투입하면 30동시통화 기준의 1차 상용 패키지로 정리할 수 있다. 이후 최종 리허설이 끝난 뒤 2개월간은 월 약 200만원 수준의 모니터링 및 추가 개선 비용을 별도로 잡는 것이 적절하다.

핵심은 단순히 화면 수를 늘리는 것이 아니라, 아직 남아 있는 상담원 업무 기능, 관리자 운영 기능, PBX 연동 안정화, 30동시통화 검증 기능을 완성하고, 운영 배포와 현장 검증까지 묶어 사업자가 고객사에 설명하고 납품 검증까지 진행할 수 있는 상태로 만드는 것이다.
