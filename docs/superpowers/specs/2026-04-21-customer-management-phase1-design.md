# 고객관리 1단계 설계

작성일: 2026-04-21  
범위: 관리자 메뉴 개편, 고객 CRUD, 고객 Import/Export, 고객 요약 노출, 고객별 수/발신 이력 조회  
비범위: 실제 080 수신거부 자동 등록/차단/멘트 재생

## 1. 목표

현재 운영 구조에는 전화번호 기반 고객 조회 백엔드가 일부 존재하지만, 관리자 앱에는 고객 관리 도메인이 없고 `080 수신거부`는 독립 블랙리스트 CRUD 화면으로 분리돼 있다.  
1단계 목표는 고객 도메인을 명확히 만들고, 실시간 통화 및 상담 흐름에서 고객 요약을 안정적으로 보여줄 수 있도록 관리자 기능과 조회 기준을 정리하는 것이다.

이번 단계에서 달성할 사용자 가치:

- 운영자가 고객을 직접 등록/수정/삭제할 수 있다.
- 운영자가 파일 Import로 고객 데이터를 일괄 적재할 수 있다.
- 운영자가 고객별 최근 수/발신 이력을 조회할 수 있다.
- 상담원/관리자 실시간 화면에서 인입 번호 기준 고객 요약을 볼 수 있다.
- 기존 `080 수신거부` 메뉴를 고객 도메인 아래의 `블랙리스트 고객 관리` 개념으로 정리할 수 있다.

## 2. 메뉴 및 권한 구조

### 2.1 관리자 메뉴

기존 단일 메뉴 `080 수신거부`를 제거하고 다음 구조로 개편한다.

- 고객관리
  - 고객 목록
  - 블랙리스트 고객 관리

기존 `운영 설정`, `보고서`, `실시간 운영` 구조는 유지한다.

### 2.2 권한 키

신규 메뉴 권한 키:

- `customers`
- `customers/blacklist`

지원 액션:

- 조회
- 등록
- 수정
- 삭제
- 내보내기

Import는 `customers`의 등록 권한에 포함한다.  
고객 상세의 최근 통화이력 조회는 `customers` 조회 권한에 포함한다.

## 3. 데이터 모델

### 3.1 고객 기본 모델

기존 Prisma 모델 `customers`, `customerPhones`를 유지하면서 운영 규칙을 명확히 한다.

`customers`

- `customerId`
- `tenantId`
- `customerName`
- `grade`: `NORMAL | VIP | BLACK`
- `memo`
- `createdAt`
- `updatedAt`
- `lastCalledAt`

`customerPhones`

- `id`
- `customerId`
- `phoneNumber`
- `normalizedPhone`
- `isPrimary`
- `isActive`

### 3.2 운영 규칙

- 고객은 대표 전화번호 1개가 필수다.
- 추가 전화번호는 0개 이상 등록 가능하다.
- 같은 tenant 안에서 하나의 정규화 전화번호는 하나의 고객에게만 연결된다.
- `grade=BLACK`는 1단계에서 고객 분류 값이며, 실제 차단 로직과는 직접 연결하지 않는다.

## 4. 화면 설계

### 4.1 고객 목록

주요 기능:

- 검색: 전화번호, 성명
- 필터: 등급, 등록일 범위, 최종통화일 범위
- 목록 컬럼:
  - 대표전화번호
  - 성명
  - 등급
  - 추가전화번호 수
  - 등록일
  - 최종통화일
  - 기본메모 요약
- 액션:
  - 등록
  - 수정
  - 삭제
  - Import
  - Export
  - 상세 보기

### 4.2 블랙리스트 고객 관리

`고객 목록`의 특화 화면으로 설계한다.

- 기본 조회 조건은 `grade=BLACK`
- 컬럼은 고객 목록과 동일하게 유지
- 운영 편의상 메모와 최종통화일을 더 강조
- 실제 080 차단 대상 관리 화면은 아니며, 고객 분류 관리 화면이다

### 4.3 고객 상세

탭 또는 단일 상세 패널로 아래를 제공한다.

- 기본 정보
- 전화번호 목록
- 최근 수/발신 이력
- 기본 메모

## 5. 고객 등록 및 Import 규칙

### 5.1 단건 등록

필수 항목:

- 대표전화번호
- 성명

선택 항목:

- 등급
- 추가 전화번호
- 기본 메모

기본값:

- 등급 기본값은 `NORMAL`

### 5.2 Import

1차 버전은 자유 형식이 아니라 템플릿 기반 Import로 제한한다.

지원 형식:

- `xlsx`
- `csv`
- `txt`(쉼표 구분)

필수 컬럼:

- `대표전화번호`
- `성명`

선택 컬럼:

- `등급`
- `추가전화번호1`
- `추가전화번호2`
- `기본메모`

처리 규칙:

- 전화번호는 모두 숫자 기준으로 정규화한다.
- 기존 고객과 대표전화번호가 중복되면 기본 동작은 `건너뛰기`로 한다.
- Import 결과는 성공/건너뜀/실패 건수와 실패 사유 목록을 반환한다.

1차 버전에서 자동 병합 또는 기존 고객 자동 덮어쓰기는 제공하지 않는다.

## 6. 실시간 고객 요약 노출

인입/발신 번호를 `customerPhones.normalizedPhone`과 매칭해서 고객 요약을 구성한다.

화면 노출 항목:

- 성명
- 등급
- 대표 전화번호
- 기본 메모
- 최종통화일
- 최근 수/발신 이력 5건

매칭되는 고객이 없으면 기존처럼 전화번호 중심으로 표시하고, `미등록 고객` 상태로 처리한다.

이 단계에서는 요약만 노출한다.  
고객 상세 전체 편집은 관리자 앱에서 수행하고, 상담원/실시간 화면은 빠른 식별 목적에 집중한다.

## 7. 고객별 수/발신 이력 조회

별도 이력 테이블을 새로 만들지 않고 기존 `callSessions`를 기준으로 조회한다.

우선순위:

1. `callSessions.customerId`
2. 보조 매칭: 고객 전화번호와 `ani` 또는 `dnis`

이력 컬럼:

- 통화일시
- 방향(수신/발신)
- 상태
- 상담원
- 분배룰
- 통화시간

`lastCalledAt`는 통화 종료 시점 갱신 대상으로 사용한다.

## 8. API 설계 방향

기존 `CustomersModule`은 `전화번호 검색`, `단건 조회`만 지원한다.  
1단계에서 다음 API를 추가한다.

- 고객 목록 조회
- 고객 단건 생성
- 고객 단건 수정
- 고객 삭제 또는 비활성 처리
- 고객 Import
- 고객 Export
- 고객 상세 이력 조회

권한 검사는 기존 관리자 권한 체계와 동일하게 메뉴 키 기준으로 붙인다.

## 9. 2단계와의 경계

다음 항목은 이번 단계에 포함하지 않는다.

- 지사 설정의 실제 080 수신거부 사용 여부와 멘트 선택
- DID 인입 시 발신번호 자동 수집
- 080 수신거부 전용 고객 목록/Export
- 실제 Asterisk 다이얼플랜 기반 차단/멘트 처리

즉 1단계는 CRM 성격의 고객 관리 정리이고, 2단계는 텔레포니 제어 기능이다.

## 10. 오류 처리 및 검증

### 10.1 오류 처리

- 필수 컬럼 누락 시 Import 전체 실패가 아니라 행 단위 실패로 처리
- 중복 전화번호는 건너뛰기 후 결과 리포트에 포함
- 잘못된 등급 값은 행 단위 실패
- 고객 삭제 시 참조 중인 통화 이력 때문에 물리 삭제가 위험하면 비활성 처리로 대체

### 10.2 검증

- 서버:
  - 고객 CRUD
  - Import 파서
  - 전화번호 중복 방지
  - 고객 요약 조회
- 관리자 앱:
  - 고객 목록 검색/필터
  - 고객 상세 이력 조회
  - Import 결과 표시
  - 블랙리스트 고객 관리 화면 필터
- 실시간 화면:
  - 인입 번호 매칭 시 고객 요약 노출
  - 미등록 번호 처리

## 11. 권장 구현 순서

1. 메뉴/권한 추가
2. 고객 목록/상세 API 확장
3. 관리자 고객 목록/상세 화면
4. Import/Export
5. 블랙리스트 고객 관리 화면
6. 실시간/상담원 고객 요약 연결

이 순서를 따르면 고객 데이터 관리 기능을 먼저 안정화하고, 이후 통화 화면 연결을 상대적으로 안전하게 검증할 수 있다.
