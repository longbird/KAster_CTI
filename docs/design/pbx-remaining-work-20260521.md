# PBX 남은 작업 실행 순서 - 2026-05-21

## 기준

- 기준 커밋: `3b9a815 feat: complete PBX M3 operations automation`
- 범위: M1~M3 구현 후 코드와 문서가 서로 어긋난 항목을 정리하고, 다음 구현 순서를 확정한다.
- 제외: 운영 DB 마이그레이션 적용, 운영 배포, 실제 운영 PBX 리로드. 이 항목들은 별도 운영 절차에서 처리한다.

## 현재 상태

- M1의 지사/DID/ARS/착신 정책, 외부 착신 방식, 내선 표시명/잠금, 국선 표시번호, 시간 동기화 상태, 공통 도움말 UI는 구현 완료 상태다.
- M2의 가상버퍼, 상담원 그룹 기반 분배, 제한적 대리응답 검증은 구현 완료 상태다.
- M3의 시간별 동작, 공휴일 지정, 국선 그룹 보류 결정은 구현 완료 상태다.
- 운영 DB 마이그레이션은 운영 서버에서 직접 적용해야 하며, 로컬 문서 작업의 완료 기준에 포함하지 않는다.

## 추천 실행 순서

### 1. 실제 PBX 시간 동기화 기준 보강 - 완료

AMI `Command` 액션으로 PBX 시간 조회 명령을 실행하고, 결과에서 시간 값을 파싱해 앱 서버 시간과 비교하도록 보강했다. 기본 명령은 `PBX_TIME_AMI_COMMAND` 환경변수로 교체 가능하며, 조회 실패 또는 파싱 실패 시 `UNKNOWN` 상태를 반환한다.

검증:

- 서버 단위 테스트: PBX 시간 조회 성공, 실패, 임계치 초과 통과.
- 관리자 테스트: 정상/주의/위험/확인 불가 표시 통과.
- 빌드: `cd apps/server; npm run build`, `cd apps/admin; npm run build` 통과.

### 2. 국선 표시번호 범위 결정 - 완료

트렁크 단위 `displayNumber`를 별도 운영값으로 추가했다. 이 값은 PBX 트렁크 목록과 트렁크 생성/수정 폼에서 관리하며, 발신번호 정책과 PBX Caller ID 렌더링을 덮어쓰지 않는다.

검증:

- 서버 테스트: 트렁크 표시번호 저장, 표시번호 자동 계산 통과.
- 관리자 테스트: PBX 설정 API mock shape 통과.
- 전체 회귀: 서버 Jest 246 PASS, 관리자 Vitest 98 PASS.

### 3. 지사별 outbound caller ID PBX 렌더링 - 완료

상담원별 outbound CID sub-context를 생성하고, 상담원의 지사 매핑에 해당하는 지사 룰과 전역 룰만 해당 상담원 발신 경로에 반영한다. 이로써 지사 지정 룰이 다른 지사 상담원에게 섞여 적용되는 문제를 피한다.

검증:

- 서버 렌더러 테스트: 전역 룰, 지사 룰, 우선순위 충돌 통과.
- reload service 테스트: 지사별 룰이 상담원 branch mapping을 통해 dialplan preview에 반영되는지 확인.
- 전체 회귀: 서버 Jest 248 PASS.

### 4. 공유 규칙 PBX 큐 멤버 동기화 - 다음 작업

관리자 공유 규칙 화면은 존재하지만 PBX 큐 멤버 동기화는 후속으로 남아 있다. 실제 운영에서 그룹 공유 규칙이 큐 멤버를 자동 조정해야 하면 동기화 작업을 추가한다.

검증:

- 서버 서비스 테스트: 그룹 변경 전후 큐 멤버 스냅샷.
- 관리자 테스트: 저장 후 동기화 상태 표시.

### 5. 운영 후속 묶음

아래 항목은 M1~M3 진척을 막지는 않지만, 운영 안정화 단계에서 순서대로 처리한다.

- 외부 연동 dry-run 해제.
- transfer candidate 만료 처리.
- 차단 이력 집계.
- 큐 요약 drill-down.
- SMDR 외부 알림 세부 연동.
