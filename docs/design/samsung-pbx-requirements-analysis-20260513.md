### 판단 원칙

- 기존 디지털 키폰 PBX는 기준점이 아니라 참조 자료다.
- 현재 개발 중인 CTI 운영에 꼭 필요한 기능만 수용한다.
- 기존 장비에 있더라도 현재 CTI 목적, 관리자 사용성, 운영 안정성에 맞지 않으면 불수용 또는 후순위로 둔다.
- 외부 문서, 관리자 화면, 운영 문구의 제품/기술 명칭은 `PBX`로 통일한다.
- 번호 자원은 기능 구현 기반이 아니라 운영 정책/충돌 검증/바로가기 인터페이스 영역으로 본다.
- 기능코드는 번호 자원과 별도 영역으로 본다.
- 실시간 감청은 지원하지 않는다.

## 2. 이번 재검토 결론

기존 문서에서 번호 자원과 기능코드를 하나의 기반으로 묶어 본 것은 과도했다. 재검토 결과, 번호 자원은 운영상 번호 대역을 제한하고 충돌을 막기 위한 정책 영역으로 정의하는 것이 더 적합하다. 기능코드는 사용자가 특정 동작을 호출하기 위한 접근 코드이므로 별도 registry로 다뤄야 한다.

또한 가상버퍼와 ARS 번호는 별도 번호 자원으로 독립 관리할 필요성이 낮다. 가상버퍼는 호 분배를 위한 내부 공간이고, ARS는 지사/DID별 인입 정책 안에서 설정하는 것으로 충분할 가능성이 높다. 다만 운영자가 화면에서 상태를 추적하거나 수동 라우팅을 해야 하는 경우에는 "번호"가 아니라 "내부 리소스 ID" 또는 "관리자 화면 바로가기"로 관리하는 편이 맞다.

| P0 | 착신전환 조건 다양화 | 수용 | 무조건/통화중/무응답/시간대/대기시간/장애 fallback 등 운영 중 필요한 조건이 많다. |

## 4. 주요 기능별 재판단

### 4.1 가상버퍼

요청 관점: 가상버퍼는 호 분배를 위한 공간이므로 별도 번호 할당 관리가 필요한지 검토.

판단:

- 호 분배 내부 공간이라면 별도 번호 자원으로 관리할 필요가 낮다.
- 상담원이나 관리자가 직접 다이얼하거나 전환 대상으로 선택해야 하는 객체가 아니라면 "번호"를 줄 이유가 없다.
- 필요한 것은 번호 대역 관리가 아니라 현재 대기/분배 상태를 보여주는 운영 화면일 가능성이 높다.

권장:

- `가상버퍼 번호`가 아니라 `분배 버퍼`, `대기 버퍼`, `분배 슬롯` 같은 내부 리소스로 정의한다.
- 관리자 화면에서는 큐/상담원그룹 상세 안에서 버퍼 상태를 보여준다.
- 외부에서 직접 접근하거나 라우팅 target으로 써야 하는 경우에만 내부 식별자를 부여한다.

### 4.2 ARS 번호

요청 관점: ARS 번호를 별도 관리할 필요가 있는지, 지사별 설정에서 ARS 설정하는 것으로 충분한지 확인.

판단:

- 별도 ARS 번호 자원 관리보다는 지사/DID별 인입 설정 안에서 ARS 메뉴를 선택하는 방식이 적합하다.
- 고객이 다이얼하는 번호는 DID이고, ARS는 그 DID 또는 지사 정책에 연결된 처리 흐름이다.
- ARS를 별도 번호로 관리하면 DID, 지사, IVR 메뉴 사이의 관계가 중복될 수 있다.

권장:

- 지사 설정 또는 DID 설정에서 `ARS 사용 여부`, `ARS 메뉴`, `timeout`, `fallback 목적지`, `업무시간/휴일 분기`를 관리한다.
- ARS 메뉴 자체는 별도 엔티티로 관리하되, 번호 자원으로는 관리하지 않는다.

### 4.3 국선번호

요청 관점: 국선번호는 보통 트렁크 번호의 마지막 4자리를 사용함.

판단:

- 별도 번호 자원으로 만들기보다 트렁크 표시명/표시번호 정책으로 두는 것이 적합하다.
- 실제 트렁크 식별자, 대표번호, 표시번호는 분리해야 한다.

권장:

- PBX Trunk에는 실제 접속 정보와 표시용 국선번호를 분리해 둔다.
- 표시용 국선번호 기본값은 트렁크 번호 또는 대표번호의 마지막 4자리로 자동 제안한다.
- 운영자가 필요한 경우만 수동 override 한다.

### 4.4 외부 착신 방식 정의

매뉴얼의 내선그룹 링 분배 방식은 다음 3가지다.

| 방식 | 정의 | 현재 CTI 해석 |
| --- | --- | --- |
| SEQUENTIAL | 항상 첫 번째 멤버부터 순서대로 탐색 | 상담원 그룹의 고정 우선순위 순차 분배 |
| DISTRIBUTE | 이전 탐색에서 선택된 멤버 다음부터 탐색 | 라운드로빈 또는 순환 분배 |
| UNCONDITIONAL | 모든 멤버에게 동시에 착신 | 동시 링 또는 전체 호출 |

매뉴얼상 내선그룹에는 overflow 시간, 그룹 전환 시간, 다음 착신 대상, 멤버별 next hunt, 전체 busy 처리, 모두 로그아웃 시 next 전환 같은 제어값도 있다.

현재 CTI 판단:

- `내선그룹`을 별도 복제하기보다 상담원 그룹/큐 분배 정책으로 흡수한다.
- 단, overflow/fallback은 운영상 중요하므로 큐/상담원그룹 설정에 포함해야 한다.

필수 정의:

- 순차 분배: 지정된 memberOrder 기준으로 호출한다.
- 순환 분배: 마지막 성공 또는 마지막 시도 위치 다음 상담원부터 호출한다.
- 동시 분배: 그룹 내 가능한 상담원에게 동시에 ringing 한다.
- overflow: 지정 시간 내 응답이 없으면 다음 큐/상담원그룹/ARS/외부번호로 넘긴다.
- all-out fallback: 그룹 멤버가 모두 로그아웃/비활성/통화불가이면 대기 없이 fallback 목적지로 넘긴다.

### 4.5 내선 잠금

판단:

- 내선 잠금은 정책 기능으로 도입 필요성이 있다.
- 매뉴얼상 잠금 해제, 국선 발신 잠금, 전체 잠금으로 나뉜다.

권장:

- 초기에는 `UNLOCKED`, `OUTBOUND_LOCKED`, `FULL_LOCKED` 정도로 단순화한다.
- 발신 제한 정책과 연동한다.
- 상담원 로그인 차단까지 포함할지는 별도 결정한다.

### 4.6 착신전환 조건 다양화

판단:

- 수용한다.
- 기존 문서의 DID 착신전환만으로는 부족하고, 운영에서는 조건이 다양해야 한다.

필요 조건:

- 무조건 전환
- 통화중 전환
- 무응답 전환
- 통화중/무응답 전환
- DND 또는 비활성 상태 전환
- 업무시간/시간대 조건
- 공휴일 조건
- 큐 대기시간 초과
- 전체 상담원 로그아웃/통화불가
- PBX/CTI 장애 fallback

### 4.7 전화기 응답 모드

매뉴얼 기준:

- `RING MODE`: 전화기에 링을 울리고 사용자가 수화기 또는 스피커로 응답한다.
- `AUTO ANSWER MODE`: 짧은 신호음 후 전화기 스피커가 자동으로 열려 통화 상태가 된다.
- `VOICE ANNOUNCE`: 링 없이 짧은 신호음 후 상대 음성이 스피커로 들리지만, 내 음성은 송출되지 않는다. 수화기 또는 스피커를 누르면 통화 상태가 된다.

판단:

- 일반 소프트폰/웹 상담원 앱에서는 `RING MODE`가 기본이다.
- `AUTO ANSWER`는 콜센터 자동응답 정책이 필요할 때만 수용한다.
- `VOICE ANNOUNCE`는 디지털 키폰 특화 기능에 가깝고, 현재 CTI의 필수 기능은 아니다.

### 4.8 내선 이름

판단:

- `내선 이름`은 내선 표시명을 뜻한다.
- 상담원명과 항상 같지 않을 수 있으므로 `extensionDisplayName` 또는 단말 표시명 필드로 분리하는 것이 적합하다.

권장:

- 상담원 이름: 사람 기준 표시명
- 내선 표시명: 단말/내선 기준 표시명
- 기본값은 상담원명으로 채우되, 운영자가 override 가능하게 한다.

### 4.9 내선별 단축 다이얼

판단:

- 기능적인 측면의 부가 기능이므로 개발 후순위다.
- 통화 라우팅/운영 안정성에 직접 필수는 아니다.

### 4.10 시간 표시 방법

판단:

- 후순위다.
- 단말 표시 옵션이며 CTI 운영 핵심 기능이 아니다.

### 4.11 통화 감청

판단:

- 불가.
- 관련 기능키, 권한, 화면, API는 제공하지 않는다.

### 4.12 내선 서비스 등급

매뉴얼 기준:

- 내선별로 링 모드 1~6에 대한 서비스 등급 01~30을 지정한다.
- 실제 서비스 등급의 내용은 서비스 등급표에서 정의하며, 국선 통화 제한 등급, 사용 가능 기능, 호출 가능한 내선그룹/국선그룹 등을 제어한다.

현재 CTI 해석:

- 기존 PBX의 COS(Class of Service)에 해당한다.
- 현재 CTI의 메뉴 권한과는 다르다.
- 상담원이 어떤 PBX 기능을 사용할 수 있는지, 어떤 발신/전환/그룹 호출이 가능한지를 제어하는 정책이다.

판단:

- 전체 COS 구조를 그대로 복제하는 것은 과하다.
- 필요한 기능 권한만 분해해서 `PBX 기능 권한 정책`으로 수용하는 것이 적합하다.
- 초기 필수는 아니며, 내선 잠금/착신전환/외부전환/당겨받기 같은 기능이 구현된 뒤 필요 범위만 도입한다.

### 4.13 대리응답 그룹

매뉴얼 기준:

- 다른 전화기에 착신되는 호를 같은 pickup group의 내선이 대신 받을 수 있게 하는 기능이다.
- 설정 방식은 그룹별 멤버 지정 또는 내선별 그룹 지정이 가능하다.

검토:

- 일반 인입 분배는 상담원 그룹/큐 분배룰로 충분하다.
- 대리응답은 이미 특정 내선에 ringing 중인 콜을 다른 상담원이 "당겨받는" 기능이므로 분배룰과 정확히 같지는 않다.

판단:

- 초기에는 상담원 그룹/큐 분배로 대체한다.
- 실제 운영에서 "옆자리 ringing 콜을 직접 당겨받기"가 필요하면 같은 상담원 그룹 안의 ringing call pickup으로 최소 구현한다.
- 별도 대리응답 그룹 모델은 후순위다.

### 4.14 통화 그룹별 발신/응답 허용

판단:

- 부가적이며 후순위다.
- 초기에는 지사/상담원/발신번호 권한과 큐/그룹 멤버십으로 충분한지 확인한다.

### 4.15 직통전화

매뉴얼 기준:

- 수화기를 들면 지정된 대기 시간 후 내선 또는 외부번호로 자동 다이얼한다.
- 외부 직통전화는 국선번호와 발신 번호를 함께 입력하는 방식이다.
- 관련 시간값은 내선 시간 변수의 `OFFHK SEL.`과 연결된다.

현재 CTI 해석:

- off-hook 자동 발신, 즉 hotline 기능이다.
- 일반 콜센터 상담원 소프트폰에서 기본 필수 기능은 아니다.

판단:

- 정확한 운영 시나리오 확인 전까지 후순위다.
- 필요하다면 특정 장비/특정 내선 프로필에만 제한적으로 제공한다.

### 4.16 브랜치 그룹

매뉴얼 기준:

- 같은 브랜치 그룹에 속한 다른 전화기에 착신되는 호를 수화기를 드는 동작만으로 대리응답할 수 있다.

현재 CTI 해석:

- 현재 `branches`의 지사 개념과 다르다.
- 기능 의미는 "오프훅 자동 당겨받기 그룹"에 가깝다.

판단:

- 정확한 운영 시나리오 확인 전까지 후순위다.
- 지사 개념과 혼동되므로 도입한다면 `오프훅 당겨받기 그룹` 같은 별도 명칭을 사용한다.

### 4.17 발신자번호 내선/국선별 등록

판단:

- 내선/국선별로 CLI 1~4와 SIP alias를 모두 등록하는 것은 현재 CTI에는 과다 스펙으로 보인다.
- 이미 발신번호 정책과 상담원/지사별 발신권한 구조가 있으므로 그 범위 안에서 처리한다.

권장:

- 내선별/국선별 CLI slot 복제는 하지 않는다.
- 지사/상담원/업무 규칙 기준의 발신번호 선택 정책으로 유지한다.

### 4.18 국선 이름

판단:

- 후순위다.
- 운영 편의용 표시명이며, 트렁크 목록의 display name 정도로 충분하다.

### 4.19 시스템 시간

판단:

- 시스템 시간 변경 기능으로 만들지 않는다.
- 시간 동기화 사용 여부, 현재 시간, NTP/서버 시간 편차, 마지막 동기화 상태를 보여주는 운영 점검 기능으로 진행한다.

### 4.20 시간별 동작

판단:

- 추가 기능이다.
- 착신전환 조건 다양화와 연결되므로, 기본 라우팅 이후 업무시간/점심시간/야간 정책으로 확장한다.

### 4.21 공휴일 지정

판단:

- 추가 기능이다.
- 지사별 휴일 캘린더와 라우팅 fallback을 연결하는 방식으로 수용한다.

### 4.22 내선 그룹 지정

판단:

- 상담원 그룹 기능으로 대체 가능하다.
- 기존 내선그룹을 그대로 복제하지 않고 상담원 그룹/큐 정책에 분배 방식과 overflow를 추가한다.

### 4.23 국선 그룹 지정

매뉴얼 기준:

- 한 개의 국선은 한 개 또는 여러 국선그룹에 속할 수 있다.
- 그룹 유형은 mixed, normal, ISDN, SIP 등으로 나뉜다.
- 탐색 방식은 순차탐색과 분배탐색이 있다.
- 최적선로선택 같은 경로 선택 기능에서 유용하게 사용된다.

현재 CTI 검토:

- 국선별 설정만으로 충분하면 국선그룹은 불필요하다.
- 여러 트렁크를 하나의 outbound pool로 묶어 장애/부하/요금/사업자별 경로 선택을 해야 할 때만 필요하다.

판단:

- 초기에는 불수용 또는 후순위다.
- 복수 트렁크 failover, 회선 부하 분산, 사업자별 발신 라우팅이 필요해지면 수용한다.

### 4.24 서비스 등급표, 공동 단축다이얼, 키버튼, 다이얼번호 변경

판단:

- 현재 필요성이 확인되지 않은 부가 기능이다.
- 후순위로 둔다.

세부 판단:

- 서비스 등급표: 전체 복제는 과함. 필요한 PBX 기능 권한만 분해 수용.
- 공동 단축다이얼: 상담 편의 기능. 고객/연락처 기능과 중복 가능.
- 내선별 키버튼/전화기 종류별 버튼: 소프트폰 UI가 확정된 뒤 필요한 기능키만 수용.
- 다이얼번호 변경: 기능코드 registry와 번호 운영 정책으로 분리. 전체 MMC식 번호 변경 UI는 만들지 않는다.

### 4.25 시스템 재시동

판단:

- 별도 기능이다.
- 설정 CRUD와 분리된 운영 액션으로 두고, 강한 권한/사유 입력/2단계 확인/감사 로그가 필요하다.

### 4.26 내선/국선 포트 초기화

매뉴얼 기준:

- 특정 내선이나 국선에 대해 호 처리 또는 DB 관련 상태를 강제로 초기화하는 기능이다.
- 선택 대상은 내선 또는 국선 번호이고, 초기화 유형은 `CALL CLEAR` 또는 `DB INITIAL`이다.

현재 CTI 해석:

- 끊기 실패, stuck call, 단말/트렁크 상태 꼬임 같은 장애 복구용 기능에 가깝다.
- 일반 운영자가 자주 쓰는 설정 기능이 아니다.

판단:

- 초기 관리자 기능으로 바로 노출하지 않는다.
- 장애 복구 runbook 또는 super admin 전용 운영 액션으로만 검토한다.
- CTI 관점에서는 먼저 stuck session recovery, 통화 강제종료, PBX endpoint 상태 재조회로 해결 가능한지 확인해야 한다.

## 6. 다음 검토 기준

다음 검토는 이 문서를 기준으로 진행한다.

1. P0 항목부터 DB/API/UI 설계로 구체화한다.
2. P1 항목은 실제 운영 시나리오가 있는지 확인한 뒤 최소 기능으로 설계한다.
3. P2/P3 항목은 초기 운영 안정화 이후 backlog로 둔다.
4. 불수용 항목은 요구사항 목록에는 남기되 구현 대상에서 제외한다.
5. 별도 운영 액션은 설정 화면과 분리해 권한, 감사, runbook 기준으로 검토한다.
