PBX 운영 환경 검증 Runbook

작성일: 2026-07-16

목적

코드와 단위 테스트로 확인한 PBX 설정 기능을 실제 운영 PBX 환경에서 검증하기 위한 절차다. 이 문서는 착신전환, 대리응답, 무조건 착신, 시간 동기화의 실제 동작 확인을 목표로 한다.

전제 조건

  • 운영 또는 리허설 PBX에 안전하게 테스트할 수 있는 DID, 상담원 내선, 호 분배룰이 준비되어 있어야 한다.
  • 테스트 고객 번호 또는 테스트 발신 회선이 준비되어 있어야 한다.
  • 관리자 앱에서 PBX 설정 미리보기와 리로드 권한을 가진 계정이 필요하다.
  • 테스트 중 실제 고객 인입이 섞이지 않도록 테스트 DID 또는 테스트 시간대를 사용한다.

공통 확인

  1. 관리자 앱에서 테스트 지사, DID, 상담원, 호 분배룰을 확인한다.
  2. PBX 설정 미리보기에서 DID 라우팅, 큐 전략, 착신전환 분기, 공휴일/시간 조건이 예상대로 렌더링되는지 확인한다.
  3. 설정 변경 후 PBX 리로드가 성공했는지 확인한다.
  4. 테스트 통화 후 통화 현황 조회, 호 로그, 미연결 콜에서 같은 linkedid 흐름이 이어지는지 확인한다.

1. 착신전환 조건 검증

즉시 전환

  1. 테스트 DID에 즉시 착신전환을 설정한다.
  2. 대상은 테스트 상담원 내선 또는 테스트 분배룰로 지정한다.
  3. 외부에서 테스트 DID로 발신한다.
  4. 원래 DID 기본 경로보다 착신전환 대상이 우선되는지 확인한다.

기대 결과:

  • 통화가 착신전환 대상에 연결된다.
  • 통화 로그에 DID와 전환 대상이 추적된다.

대기시간 초과 전환

  1. 테스트 DID의 기본 경로를 테스트 분배룰로 지정한다.
  2. 착신전환 조건을 대기시간 초과로 설정한다.
  3. 상담원을 모두 통화불가 또는 미응답 상태로 둔다.
  4. 외부에서 테스트 DID로 발신한다.

기대 결과:

  • 지정 대기시간 이후 fallback 대상에 연결된다.
  • 큐 대기시간과 전환 시간이 운영 화면에 일관되게 표시된다.

상담원 없음 전환

  1. 테스트 분배룰의 상담원을 모두 로그아웃 또는 비활성 상태로 만든다.
  2. 상담원 없음 조건 착신전환을 설정한다.
  3. 외부에서 테스트 DID로 발신한다.

기대 결과:

  • 큐 대기 없이 fallback 대상에 연결된다.

2. 대리응답 검증

같은 그룹 또는 같은 분배룰

  1. 상담원 A와 상담원 B를 같은 상담원 그룹 또는 같은 호 분배룰에 배치한다.
  2. 상담원 A 대상 또는 해당 분배룰 대상 통화를 발생시킨다.
  3. 상담원 B 계정에서 실시간 콜 화면의 대리응답 대상 통화를 선택한다.

기대 결과:

  • 대리응답 요청이 수락된다.
  • 상담원 B가 통화를 받는다.
  • 중복 대리응답 요청은 실패하거나 무시된다.

다른 그룹 또는 다른 분배룰

  1. 상담원 C를 다른 그룹 또는 다른 분배룰에 배치한다.
  2. 상담원 C 계정에서 같은 통화에 대리응답을 시도한다.

기대 결과:

  • 권한 또는 범위 제한으로 대리응답이 거부된다.

3. 무조건 착신 검증

상담원 대상

  1. 호 분배룰의 외부 착신 방식을 무조건으로 설정한다.
  2. 대상 유형을 상담원으로 지정한다.
  3. 테스트 DID를 해당 호 분배룰에 연결하고 외부 발신한다.

기대 결과:

  • 지정 상담원에게 즉시 연결된다.

호 분배룰 대상

  1. 무조건 착신 대상 유형을 다른 호 분배룰로 지정한다.
  2. 자기 자신을 대상으로 지정할 수 없는지 확인한다.
  3. 외부 발신 후 대상 호 분배룰로 연결되는지 확인한다.

기대 결과:

  • 자기 참조는 저장 단계에서 거부된다.
  • 정상 대상은 지정된 호 분배룰로 연결된다.

외부번호 대상

  1. 무조건 착신 대상 유형을 외부번호로 지정한다.
  2. 테스트 외부번호를 입력한다.
  3. 외부 발신 후 외부번호로 전환되는지 확인한다.

기대 결과:

  • 외부번호 형식 검증을 통과한 경우에만 저장된다.
  • 통화가 외부번호로 연결된다.

4. 시간 동기화 검증

  1. 시스템 설정 화면에서 시간 동기화 상태를 조회한다.
  2. appTime, pbxTime, driftSeconds, status를 기록한다.
  3. PBX 시간 조회가 실패할 경우 UNKNOWN 상태와 오류 메시지가 표시되는지 확인한다.
  4. 착신전환 시간 조건 테스트와 같은 시점에 drift가 허용 범위인지 확인한다.

기대 결과:

  • 정상 상태에서는 앱 서버와 PBX 기준 시간 차이가 운영 허용 범위 안에 있다.
  • PBX 시간 조회 실패 시 설정 변경은 막지 않더라도 운영자가 위험을 인지할 수 있다.

5. 다중 국선 장애 우회 검증

사전 준비

  1. 테스트 가능한 국선 트렁크를 2개 이상 준비한다.
  2. 각 트렁크의 통신사, 표시번호, 인증 방식, 사용 목적, 장애 테스트 가능 여부를 기록한다.
  3. PBX 설정 > 트렁크에서 각 트렁크가 정상 등록 또는 발신 가능 상태인지 확인한다.
  4. PBX 설정 > 트렁크 > 국선 그룹에서 테스트 기본 발신 그룹을 만든다.
  5. 그룹 멤버 우선순위는 주 회선 100, 백업 회선 200처럼 명확히 둔다.
  6. 테스트 상담원은 직접 SIP 발신이 허용되어 있어야 하며 기본 발신번호가 설정되어 있어야 한다.

정상 발신

  1. 기본 국선 그룹을 활성화한다.
  2. 상담원 단말 또는 CTI 발신 경로에서 외부 테스트 번호로 발신한다.
  3. PBX 로그에서 Dial(PJSIP/...@trunk-...) 대상이 국선 그룹 멤버 순서대로 생성되는지 확인한다.
  4. 통화가 정상 연결되는지 확인한다.

기대 결과:

  • 발신이 성공한다.
  • 설정 미리보기의 extensions_agent.conf에 국선 그룹 멤버가 반영된다.
  • 운영 로그에서 어느 트렁크가 실제 연결되었는지 식별 가능해야 한다. 현재 CTI가 실제 사용 트렁크를 DB에 저장하지 못하면 후속 구현 항목으로 기록한다.

주 회선 장애 우회

  1. 테스트 시간에 주 회선을 장애 상태로 만든다.
  2. 가능한 방식: 테스트 PBX에서 주 트렁크 비활성화, 잘못된 host로 변경, 통신사 테스트 차단, 또는 안전한 네트워크 차단.
  3. 백업 회선은 정상 상태로 유지한다.
  4. 외부 테스트 번호로 발신한다.
  5. 발신이 백업 회선으로 성공하는지 확인한다.
  6. 실패 시 PBX 로그의 Dial 실패 코드와 시도 순서를 기록한다.

기대 결과:

  • 주 회선 장애 시 백업 회선으로 발신이 성공한다.
  • 실패 원인이 주 회선 장애인지, 발신번호/인증/라우팅 정책 문제인지 구분된다.

원복 검증

  1. 주 회선을 정상 상태로 복구한다.
  2. 동일 번호로 다시 발신한다.
  3. 발신 경로가 주 회선을 다시 사용할 수 있는지 확인한다.

기대 결과:

  • 현재 구현은 국선 그룹 우선순위 기반이므로 주 회선이 정상화되면 우선순위상 주 회선을 다시 사용할 수 있어야 한다.
  • 자동 health 판단과 동적 제외/복귀는 아직 구현 범위가 아니므로, 필요하면 별도 요구로 기록한다.
