# PBX 후순위/정의 필요 기능 백로그

## 목적

현재 CTI 운영 핵심 경로에 포함하지 않는 PBX 기능을 별도 백로그로 보관한다. 이 문서는 미구현 기능을 즉시 개발 대상으로 오인하지 않기 위한 보류 근거다.

## 후순위 전화기 부가 기능

- 내선별 단축 다이얼
- 공동 단축 다이얼
- 시간표시 방법
- 서비스 등급표
- 통화 그룹별 발신/응답 허용
- 내선별 키버튼
- 전화기 종류별 버튼
- 다이얼번호 변경

승격 조건:

- 실제 단말 모델과 프로비저닝 방식이 확정된다.
- 운영자가 CTI 웹/관리자 앱에서 해당 기능을 반드시 관리해야 하는 현장 시나리오가 확인된다.
- PBX 렌더러와 충돌 검증을 테스트로 고정할 수 있다.

키버튼/전화기 종류별 버튼 보류 사유:

- PBX는 단말 버튼의 물리 위치, 라벨, LED, soft key 배열을 직접 제어하지 않는다.
- PBX가 해석하는 것은 단말이 버튼 입력 후 송신한 SIP 요청, DTMF, 기능코드, `SUBSCRIBE/NOTIFY` 같은 신호다.
- 버튼 매핑은 전화기 제조사와 모델별 프로비저닝 파일에서 정해진다.
- 제조사별로 line key, DSS key, memory key, BLF key, transfer key 같은 명칭과 설정 포맷이 다르다.
- 따라서 지원 단말 모델과 프로비저닝 방식이 확정되지 않으면 PBX 설정만으로 “전화기 종류별 버튼”을 일관되게 구현할 수 없다.

현재 PBX에서 수용 가능한 대체 범위:

- 대리응답, 단축 발신, 내선 호출처럼 버튼이 보낼 기능코드 또는 번호를 PBX dialplan에서 처리한다.
- 단말이 BLF용 `SUBSCRIBE`를 보낸다는 전제에서 BLF 상태 제공 가능성을 별도 검토한다.
- 버튼 배치와 라벨은 단말 프로비저닝 기능이 생기기 전까지 CTI 구현 범위에 포함하지 않는다.

서비스 등급표 처리 원칙:

- 기존 PBX COS를 그대로 복제하지 않는다.
- 발신 제한, 국제전화 제한, 관리자 권한, 지사별 발신번호 권한 같은 개별 정책으로 분해한다.

## 직통전화

현재 결론: DID 직접 착신과 tenant 공용 단축 발신은 구현 완료, 오프훅 자동 발신은 보류.

확인할 의미:

- 수화기를 들면 자동으로 지정 대상에 발신하는 오프훅 자동 발신인지
- DID가 특정 상담원/호 분배룰로 직접 들어오는 DID 직접 착신인지: 구현 완료
- 외부번호 단축 발신인지: tenant 공용 단축 발신으로 구현 완료

처리 원칙:

- DID 직접 착신은 DID 원천 설정의 `IVR / 큐 직결 / 내선 직결` 중 하나로 처리한다.
- 단축 발신은 PBX 설정의 단축 발신 탭에서 tenant 공용 단축번호로 관리한다.
- 오프훅 자동 발신이면 후순위 전화기 단말 정책으로 분류한다.

구현 상세:

- `AsteriskDid.directExtension`으로 DID 내선 직결 대상을 저장한다.
- DID 라우팅은 `ivrMenuId`, `directQueue`, `directExtension` 중 하나만 허용한다.
- `AsteriskSpeedDial`로 tenant 공용 단축번호를 저장한다.
- `agent-phone-{내선}` context에서 단축번호를 실제 대상번호로 변환한다.
- 단축번호 대상이 내선이면 내부 `Dial(PJSIP/{내선})`로 연결하고, 외부번호이면 기존 outbound context로 넘긴다.

관리자 화면:

- DID 직접 착신: `PBX 설정 > DID`
- 단축 발신: `PBX 설정 > 단축 발신`

보류 유지 범위:

- 수화기를 들기만 하면 자동 발신되는 오프훅 자동 발신
- 상담원별 개인 단축 다이얼
- 전화기 단말 키버튼 프로비저닝

## 브랜치 그룹

현재 결론: pickup group 의미는 대리응답 기능으로 부분 흡수, 나머지 구현 대상 승격 보류.

확인할 의미:

- 지사 그룹인지
- 전화기 단말의 pickup group인지

처리 원칙:

- 지사 그룹이면 CTI `branches` 화면의 조직/권한 정책과 분리해 명칭을 확정한 뒤 설계한다.
- pickup group이면 대리응답 정책과 함께 설계한다. 현재 구현 가능한 범위는 같은 상담원 그룹 또는 같은 호 분배룰 범위의 대리응답이며, 실시간 콜 화면의 대리응답 진입과 도움말로 연결한다.

## 국선 그룹

현재 결론: 기본 발신 풀과 장애 우회 순서는 구현 완료, 고급 라우팅은 보류.

구현 완료 범위:

- 국선 그룹과 멤버를 tenant 기준으로 관리한다.
- 기본 발신 그룹은 tenant 기준 1개만 유지한다.
- 기본 그룹의 활성 멤버를 우선순위 순서로 PBX 발신 Dial 대상에 반영한다.
- 관리자 PBX 설정 화면에서 국선 그룹을 추가, 수정, 삭제한다.

보류 유지 범위:

- 지사별 국선 그룹 선택
- 요금제/통신사/지역별 발신 라우팅
- 회선 품질 또는 장애 상태를 실시간으로 판단하는 동적 라우팅

승격 조건:

- 지사별로 서로 다른 국선 풀을 반드시 사용해야 하는 운영 정책이 확정된다.
- 통신사별 요금 또는 지역별 발신 제약이 실제로 존재한다.
- PBX 또는 통신사 장애 감지 기준을 수집할 수 있다.

추가 구현 전에 정리할 사항:

| 영역 | 확인 필요 사항 |
|---|---|
| 회선 인벤토리 | 트렁크별 통신사, 인증 방식, 대표번호, 사용 목적, 백업 여부 |
| 장애 판단 | SIP 등록 실패, OPTIONS 실패, Dial 실패 코드, 통화 실패율 중 어떤 기준을 사용할지 |
| 장애 우회 방식 | PBX Dial 대상 병렬/순차 구성으로 충분한지, CTI가 상태를 보고 동적으로 제외해야 하는지 |
| 원복 정책 | 장애 회선이 정상화되었을 때 자동 복귀할지, 운영자가 수동 복귀할지 |
| 지사별 라우팅 | 상담원 지사, DID 지사, 발신번호 권한 중 어떤 값을 기준으로 국선 그룹을 선택할지 |
| 사업자별 라우팅 | 목적지 번호 prefix, 통신사, 요금제, 지역번호 기준 라우팅이 필요한지 |
| 예외 번호 | 긴급번호, 특수번호, 국제전화, 수신자부담번호 처리 정책 |
| 감사/로그 | 발신 call leg에 실제 사용 국선 그룹/트렁크를 기록할지 |

현 구현 기준:

- 기본 발신 국선 그룹은 구현되어 있다.
- 그룹 멤버 우선순위는 PBX 발신 Dial 대상에 반영된다.
- 지사별/사업자별 라우팅 룰과 trunk health 기반 동적 제외는 아직 없다.
