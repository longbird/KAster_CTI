## 0. 한 줄 요약

**고객이 누른 번호로 외부 시스템에 물어보고, 그 답으로 통화를 다르게 흘린다.**
"고객번호 입력 → CRM 조회 → VIP면 전용 큐, 아니면 일반 큐" 가 대표 사례다.

이 문서의 대부분은 "무엇을 만들까" 가 아니라 **"조회가 실패할 때 고객이 어떻게 되는가"** 다.
외부 HTTP 는 통화 경로에서 유일하게 **우리 통제 밖에서 느려지거나 죽는 지점**이다.

---

## 1. 왜 이것만 별도 설계서인가

노드 8종(+`COLLECT_DIGITS`)은 전부 **렌더러가 이미 낼 수 있는 dialplan 문법**이었다.
`HTTP_LOOKUP` 만 진짜 새 원시연산이고, 새로 정해야 할 것이 넷이다 — 타임아웃, 재시도,
실패 폴백, 시크릿 보관. 상위 설계서 D3 이 이 넷을 이유로 미뤘다.

여기에 하나가 더 있다. **외부가 우리 dialplan 에 문자열을 넣는 첫 경로**다 (§6.3).

---

## 2. 누가 HTTP 를 부르는가

두 갈래가 있다.

| | Asterisk 가 직접 (`CURL()`) | **NestJS 가 대신 (채택)** |
|---|---|---|
| 시크릿 위치 | `/etc/asterisk` 의 conf 평문 | DB 암호화 + env 키 |
| 타임아웃·차단기 | dialplan 으로 표현 불가 | TypeScript 로 구현 |
| 응답 파싱 | `JSON_DECODE` 유무가 버전마다 다름 | 서버에서 안전하게 |
| SSRF 방어 | 없음 | 등록 + 주소 검사 |
| 감사·지표 | 없음 | 기존 `monitoring` 재사용 |
| NestJS 장애 시 | 영향 없음 | **폴백 분기로 흐른다** (§5) |

**NestJS 를 통한다.** 마지막 줄이 유일한 단점인데, 그건 설계로 흡수할 수 있고
시크릿이 PBX conf 평문에 남는 것은 흡수할 수 없다.

### D1 (컴파일 우선)과 충돌하지 않는가

상위 설계 D1 은 "미들웨어가 죽어도 전화는 계속 받는다" 였다. `HTTP_LOOKUP` 은 정의상
런타임 호출이라 그 원칙의 예외처럼 보인다. 예외가 아니다 — **실패를 1급 분기로 만든다.**

NestJS 가 죽었으면 조회는 즉시 실패하고 통화는 `FALSE` 간선으로 간다.
그 간선이 어디로 가는지는 **플로우 작성자가 정하고, 검증기가 존재를 강제한다**(§7).
즉 미들웨어 장애는 "ARS 가 멈춤" 이 아니라 "조회 없이 평소 경로로 감" 이 된다.

이미 같은 판단의 선례가 있다. `kaster-agent-offer.agi` 는 서버가 죽으면 **ACCEPT 로 연다** —
"확인 절차가 고장난 것과 전화를 못 받는 것 중에서는 전자가 낫다".

---

## 3. `System()` 이 아니라 AGI

기존 훅(수신거부·Smart ARS)은 `System()` 이고 `${SYSTEMSTATUS}` 의 성공/실패 두 값만 본다.
`HTTP_LOOKUP` 은 **값**을 되받아야 하므로 그것으로는 안 된다.

`kaster-agent-offer.agi` 가 이미 쓰는 방식을 그대로 따른다 — Python3 AGI 가 서버에 붙어
`SET VARIABLE` 로 채널 변수를 채운다. 새 기법이 아니다.

```
AGI(/var/lib/asterisk/sounds/custom/kaster-ars-http-lookup.agi,<endpointId>)
```

AGI 가 채우는 변수:

| 변수 | 값 |
|---|---|
| `ARS_LOOKUP_STATUS` | `MATCH` / `NOMATCH` / `ERROR` |
| `ARS_LOOKUP_VALUE` | 추출한 값 (§6.3 의 제약을 통과한 것만) |

인자는 `endpointId` 하나다. 나머지(테넌트·발신번호·입력값·DID·linkedid)는 AGI 가
`GET VARIABLE` 로 채널에서 읽는다 — dialplan 인자에 값이 늘어날수록 인용 규칙이 깨지기 쉽다.

### 컴파일 결과

```asterisk
 same => n(node-3-lookup),NoOp(ARS node 고객조회)
 same => n,Playback(<조회 중 안내>)                  ; 선택
 same => n,AGI(/var/.../kaster-ars-http-lookup.agi,<endpointId>)
 same => n,GotoIf($["${ARS_LOOKUP_STATUS}"="MATCH"]?<TRUE 목적지>)
 same => n,<FALSE 목적지>
```

간선 조건은 `CONDITION` 노드와 같은 `TRUE`/`FALSE` 를 쓴다. **새 간선 종류를 만들지 않는다.**

## 4. 엔드포인트를 플로우에 적지 않는다

**노드 config 에 URL 을 적을 수 없게 한다.** 대신 관리자가 먼저 **엔드포인트를 등록**하고,
노드는 `endpointId` 만 가리킨다.

이유 셋:

1. **SSRF.** 플로우 편집 권한이 있는 사람이 임의 URL 을 적을 수 있으면 PBX 망 안에서
   아무 데나 부를 수 있다. 클라우드 메타데이터 주소(`169.254.169.254`)가 대표 표적이다.
2. **시크릿.** 그래프는 미리보기·diff·백업으로 여기저기 복사된다. 자격증명이 거기 있으면 안 된다.
3. **변경 범위.** 주소가 바뀌면 그 주소를 쓰는 플로우를 전부 고쳐야 한다. 등록해 두면 한 곳이다.

### `arsHttpEndpoints` (신규 테이블)

| 컬럼 | 설명 |
|---|---|
| `endpointId` / `tenantId` | 키 |
| `name` | 관리자에 보이는 이름 |
| `method` | `GET` / `POST` |
| `url` | https 고정 (§6.1 예외 있음) |
| `requestMapping` | 무엇을 보낼지 (§4.1) |
| `authType` / `authSecretEnc` | `NONE` / `BEARER` / `HEADER`. 시크릿은 암호문 |
| `resultPath` | 응답에서 값을 꺼낼 점 표기 경로 (`data.grade`) |
| `matchMode` / `matchValue` | `EXISTS` / `EQUALS` / `IN` |
| `timeoutMs` | 기본 2000, 상한 5000 |
| `isActive` | |

**권한은 `admin` 만.** 플로우 편집은 `supervisor` 도 하지만 엔드포인트 등록은 외부 통신을
여는 행위라 등급이 다르다. 기존 `asterisk` 메뉴 키를 그대로 쓰되 `create/update/delete` 는 admin 으로 제한한다.

### 4.1 요청 매핑 — 템플릿 언어를 만들지 않는다

`{{ }}` 같은 자유 템플릿은 그 자체가 주입 표면이다. **고정된 목록에서 고른다.**

```
requestMapping: { "custNo": "COLLECTED", "phone": "CALLER", "did": "ENTRY_DID", "src": "LITERAL:kaster" }
```

허용 값은 `CALLER` / `COLLECTED` / `ENTRY_DID` / `LINKEDID` / `LITERAL:<문자열>` 다섯 뿐이다.
`GET` 이면 쿼리스트링, `POST` 면 JSON 본문으로 나간다.

### 4.2 응답 추출 — 점 표기만

`resultPath` 는 `data.customer.grade` 같은 **점 표기**만 받는다. 배열 인덱스도 JSONPath 도 없다.
없는 경로면 `NOMATCH` 다(오류가 아니다 — "그 고객이 없다" 는 정상 결과다).

## 5. 실패했을 때 고객이 어떻게 되는가

여기가 이 설계의 본체다.

### 5.1 타임아웃 — 통화는 기다리는 중이다

기본 **2초**, 상한 **5초**. 상한이 낮은 이유는 하나다 — 그 시간 동안 고객은 **무음을 듣는다.**
5초 무음이면 사람은 전화가 끊긴 줄 안다.

타임아웃은 두 겹이다.

1. NestJS → 외부: `endpoint.timeoutMs`
2. AGI → NestJS: `endpoint.timeoutMs + 500ms`

바깥 겹이 더 길어야 "서버는 답을 만들었는데 AGI 가 먼저 포기" 하는 어긋남이 안 생긴다.

### 5.2 재시도 — **하지 않는다**

계획서가 "재시도를 설계하라" 고 했고, 설계한 답은 **통화 중에는 재시도하지 않는다** 이다.

재시도는 고객의 대기 시간을 배로 늘린다. 외부가 느려서 실패한 상황에서 한 번 더 부르면
2초가 4초가 된다. 실패의 답은 다시 부르는 것이 아니라 **폴백 분기로 빠지는 것**이다.

> 배치 처리라면 재시도가 맞다. 사람이 수화기를 들고 기다리는 경로에서는 아니다.

### 5.3 차단기 — 죽은 엔드포인트를 매 통화마다 기다리지 않는다

엔드포인트가 죽으면 재시도를 안 해도 **통화마다 2초씩** 잃는다. 100통이면 200초다.

- 60초 안에 **5회 연속 실패** → 그 엔드포인트를 60초간 **열림(open)** 으로 두고,
  그동안은 외부를 부르지 않고 즉시 `ERROR` 를 준다.
- 열림이 풀릴 때 한 통만 시험 삼아 보낸다(half-open). 성공하면 닫는다.

임계값은 **env 로 빼지 않는다.** 튜닝 대상이 아니라 안전선이다 — 렌더 가드 임계값과 같은 이유다.

### 5.4 동시 실행 상한

엔드포인트당 동시 20건. 인입 폭주 때 느린 외부 하나가 Node 이벤트 루프와 소켓을 다 먹는 것을 막는다.
상한을 넘은 요청은 기다리지 않고 즉시 `ERROR` 다 — 큐에 쌓아 두면 그게 곧 지연이다.

### 5.5 `NOMATCH` 와 `ERROR` 를 같은 간선으로 보낸다

간선은 `TRUE`/`FALSE` 둘이고, `NOMATCH` 와 `ERROR` 는 **둘 다 `FALSE`** 다.

이렇게 하는 이유: 셋으로 나누면 작성자가 `ERROR` 간선을 비워 둘 수 있고, 그러면 장애 때
통화가 아무 데도 못 간다. 둘로 묶으면 **폴백은 항상 하나뿐이고 반드시 채워야 한다.**

구분이 사라지는 것은 아니다. `ARS_LOOKUP_STATUS` 에 남고, 지표와 로그에서 갈라 본다.
운영에서 "조회 실패만 따로 사람에게 돌리고 싶다" 는 요구가 실제로 나오면 그때 간선을 늘린다.

### 5.6 조회 중 무음 문제

2초라도 무음은 나쁘다. 엔드포인트가 아니라 **노드**에 `waitPromptKey` 를 두어
AGI 앞에서 짧은 안내("확인 중입니다")를 튼다. 선택 항목이고, 비워 두면 무음이다.

> `Playback()` 은 끝날 때까지 막는다. 안내가 2초면 총 대기가 4초가 된다.
> 편집기에서 **안내 길이 + 타임아웃**을 합쳐 보여주고, 합이 5초를 넘으면 경고한다.

## 6. 보안

### 6.1 주소 검사 (SSRF)

등록 시점과 **호출 시점 둘 다** 검사한다. 등록 때만 하면 DNS 를 나중에 바꿔치기할 수 있다.

- `https` 만. `http` 는 사설 대역(RFC1918)일 때만 허용하고 관리자 화면에 경고를 띄운다.
- 호스트를 실제로 **해석해서 나온 IP** 를 본다. 막는 대역:
  링크로컬(`169.254.0.0/16`, 클라우드 메타데이터), 루프백, `0.0.0.0/8`, 멀티캐스트, IPv6 대응 대역.
- 리다이렉트를 따라가지 않는다(`redirect: 'manual'`). 3xx 는 `ERROR` 다 —
  리다이렉트는 검사한 주소를 우회하는 가장 쉬운 길이다.

### 6.2 시크릿

- `authSecretEnc` 는 AES-256-GCM 암호문으로 저장한다. 키는 `ARS_HTTP_SECRET_KEY` (env).
  녹취 암호화와 **같은 방식이되 다른 키**다 — 용도가 다른 키를 겹쳐 쓰면 하나가 새면 둘 다 샌다.
- API 로 **절대 돌려주지 않는다.** 조회 응답에는 `hasSecret: true/false` 만 담는다.
- 오류 메시지에 넣지 않는다. 실패는 "어떤 엔드포인트가 몇 번으로 실패" 까지만 남긴다.

### 6.3 외부 문자열이 dialplan 으로 들어온다 — 가장 위험한 지점

`ARS_LOOKUP_VALUE` 는 **외부 시스템이 내용을 정하는 첫 문자열**이다. 이 값이 채널 변수에 들어가고
이후 `Goto`·`Playback`·`System()` 인자로 흘러갈 수 있다.

서버에서 **꺼내는 즉시** 깎는다. 통과하지 못하면 `ERROR` 다(잘라서 쓰지 않는다 — 잘린 값은 다른 값이다).

- 최대 64자
- 허용 문자: 영숫자, `_`, `-`, `.`, 한글
- 개행·따옴표·백틱·`$`·`{`·`}`·`,`·`;` 는 하나라도 있으면 거부
- 응답 본문 자체도 **64KB 상한**. 넘으면 읽지 않고 `ERROR` (통화 중에 큰 본문을 버퍼링하지 않는다)

### 6.4 기능 자격

**`ars-http-lookup` 키를 새로 만든다.** `ars-flow-builder` 와 분리하는 이유는,
"플로우는 쓰되 외부 호출은 못 하게" 가 실제로 있을 법한 조합이기 때문이다.
env 킬 스위치 `ARS_HTTP_LOOKUP_ENABLED=false` 가 기본값이고 최종 거부권을 갖는다(4계층 모델 그대로).

## 7. 검증기에 추가할 검사

| # | 검사 | 등급 |
|---|---|---|
| 10 | `HTTP_LOOKUP` 의 `endpointId` 가 실재하고 활성이다 | error |
| 11 | **`FALSE` 간선이 반드시 있다** | error |
| 12 | `TRUE` 간선이 없으면 조회할 이유가 없다 | warning |
| 13 | 한 통화 경로에 `HTTP_LOOKUP` 이 2개를 넘지 않는다 | error |
| 14 | `waitPromptKey` 길이 + `timeoutMs` 합이 5초를 넘는다 | warning |

11번이 §5 전체를 강제하는 검사다. **폴백 없는 조회 노드는 저장할 수 없다.**

13번은 대기 시간 누적을 막는다. 2개면 최악 10초다.

`HTTP_LOOKUP` 은 사람의 입력을 기다리지 않으므로 **순환 탈출 지점이 아니다** —
`MENU`/`COLLECT_DIGITS` 와 달리 `TRAPPED_CYCLE` 검사에서 빼지 않는다.
조회를 반복하는 순환은 외부를 무한히 두드리는 것이라 반드시 막아야 한다.

## 8. 관측

새 테이블을 만들지 않는다. 기존 `monitoring`(prom-client)에 지표를 붙인다.

- `kaster_ars_http_lookup_total{endpoint,status}` — `MATCH`/`NOMATCH`/`ERROR`/`BREAKER_OPEN`
- `kaster_ars_http_lookup_duration_seconds{endpoint}`

본문은 저장하지 않는다(개인정보). 실패는 Nest 로거에 `endpointId`·`linkedid`·HTTP 상태까지만 남긴다.
통화별 추적이 필요하면 `linkedid` 로 `rawAmiEvents` 와 맞춘다.

## 9. 단계

| 단계 | 내용 | PBX 접촉 |
|---|---|---|
| P1 | 엔드포인트 레지스트리 + 조회 서비스 + 주소 검사 + 차단기 + 관리자 화면 **"테스트 호출"** | 없음 |
| P2 | AGI + 컴파일러 + `HTTP_LOOKUP` 노드 + 검증기 10~14 + 편집기 | 렌더만 |
| P3 | 파일럿 DID 실통화 | 있음 |

**P1 이 통화 경로를 전혀 건드리지 않고 끝난다.** 외부 연동의 어려운 부분(인증·주소·응답 형태)을
전화를 걸기 전에 관리자 화면에서 다 맞출 수 있다. P1 없이 P2 를 시작하지 않는다.

## 10. env 추가

```
ARS_HTTP_LOOKUP_ENABLED=false      # 마스터 스위치. 최종 거부권
ARS_HTTP_SECRET_KEY=               # 엔드포인트 자격증명 암호화 키 (32바이트 hex)
```

타임아웃·차단기·동시 실행 상한은 **env 로 빼지 않는다** (§5.3 의 이유).
엔드포인트별 타임아웃만 DB 에 두고 상한을 코드로 묶는다.

## 11. 결정이 필요한 것

1. **`NOMATCH` / `ERROR` 를 하나의 `FALSE` 로 묶는다** (§5.5). 나중에 나누는 것은 쉽고
   지금 나눴다가 비어 있는 간선을 만드는 것은 위험하다. 이대로 갈지.
2. **조회 중 안내를 노드에 둔다** (§5.6). 아니면 아예 무음으로 두고 타임아웃을 1초로 낮출지.
3. **엔드포인트 등록을 admin 전용으로 제한** (§4). supervisor 도 허용할지.

## 12. 승인 요청

P1 (§4·§5·§6) 착수 승인이 필요하다. 되돌리기 비싼 것은 둘이다.

- **§4** — URL 을 노드가 아니라 엔드포인트 레지스트리에 두는 구조
- **§5.5** — 실패 간선을 하나로 묶고 검증기가 강제하는 것
