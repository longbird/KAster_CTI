# IPCC 시스템 구축 최종 제안안

작성일: 2026-08-04

## 1. 제안 범위

본 제안은 KAster_CTI를 기반으로 K-CTI 솔루션을 구축하는 안이다. 별도 상용 CTI, IVR, 녹취 패키지는 도입하지 않고, 현재 프로젝트 기능을 현장 PBX, 외부 API, 녹취 저장소와 연결한다.

구성 기준은 다음과 같다.

| 구분 | 구성 |
|---|---|
| 운영 서버 | PBX, IVR, CTI, 녹취 기능을 1대의 통합 서버에서 운영 |
| 백업 서버 | 백업용 통합 서버 1대 |
| DB | PostgreSQL 복제 구성을 적용한 DB 서버 2대 |
| 스토리지 | 녹취 저장 및 DB 백업용 스토리지 서버 1대 |
| OS | Ubuntu Server 24.04 LTS |
| 상담원 규모 | 상담원 100명 동시 접속 기준 |
| 통화 규모 | 100명 동시 통화 가능성을 고려해 고객 leg + 상담원 leg 기준 200채널 전후 검증 |
| 견적 범위 | 장비, 회선, AI센터 사용료, 상대 업체 연동 지원비는 별도 |

## 2. 시스템 구성도

구성도 파일: [ipcc-system-configuration-diagram.png](D:/Work/AI_Projects/KAster_CTI/docs/design/assets/ipcc-system-configuration-diagram.png)

```text
PSTN / SIP Trunk
  -> 방화벽 / SBC
  -> 통합 서버 1대
       - PBX 호처리 / Queue
       - IVR / ARS / TTS 정책
       - K-CTI Engine / WebSocket
       - AMI 이벤트 / Outbox
       - 녹취 로컬 스풀
       - 콜마너 인입 연동 모듈
  -> 상담원 웹 앱 / 관리자 웹 앱 / 외부 솔루션 연동 앱
  -> DB 본 서버 / DB 복제 서버
  -> 녹취 저장 및 DB 백업 스토리지

장애 시:
PSTN / SIP Trunk
  -> 방화벽 / SBC 절체
  -> 백업용 통합 서버
  -> DB 복제 서버 및 스토리지 기준 복구
```

## 5. 장비 선정 기준

장비는 고객 요구사항 중 안정성, 백업, 보안, 100명 상담원 처리, 녹취 3년 보관을 만족시키기 위해 선정한다.

| 장비 | 선정 기준 | 만족하는 고객 요구사항 |
|---|---|---|
| 통합 서버 1대 | PBX/IVR/K-CTI/녹취 로컬 스풀을 한 서버에서 처리. 100명 접속과 140~200채널급 이벤트 처리 | PBX, IVR, CTI, Queue, 상담원 상태, 통화 제어, 녹취 |
| 백업용 통합 서버 1대 | 본 서버 장애 시 PBX/IVR/K-CTI/녹취 기능 대체. 설정 동기화 필요 | 이중화, 장애 시 백업 시스템 절체 |
| DB 서버 2대 | PostgreSQL streaming replication, Redis/상태 캐시 구성 | 통화 이력, 고객 이력, 통계, 감사 로그, 장애 복구 |
| 스토리지 서버 1대 | 녹취 파일 3년 보관, DB 백업 저장, 스냅샷/암호화 | 녹취 보관, DB 백업, 감사 대응 |
| 방화벽/SBC | SIP Trunk 경계 보호, VPN, 관리자 접근 제어, 200~300 세션급 | 음성/데이터 보안, 접근 제어, 외부망 보호 |
| L3/PoE 스위치 | 음성/서버/관리/스토리지 VLAN 분리, IP폰 PoE 공급 | 상담원 100명, IP폰, QoS, 망 분리 |
| UPS | 통합 서버/DB/스토리지의 단기 전원 장애 대응 | 안정성, 장애 방지, 녹취 손실 방지 |

## 6. 통합 서버 처리 가능성

상담원 100명 동시 접속 자체는 통합 서버에서 처리 가능하다. 웹 상담 앱과 관리자 앱의 WebSocket 100~150 연결은 CPU/RAM 부하가 크지 않다.

핵심은 동시 통화 수와 PBX 채널 정의다. 100명이 동시에 통화하면 고객 leg와 상담원 leg가 각각 생기므로 200채널 전후를 고려해야 한다.

| 판단 항목 | 검토 |
|---|---|
| 100명 동시 로그인/접속 | 가능. Node/NestJS + WebSocket 100~150 연결은 통합 서버에 큰 부담이 아님 |
| 100명 동시 통화 | 가능하나 PBX 채널 산정 주의. 고객 leg + 상담원 leg로 200채널 전후가 될 수 있음 |
| 140채널 요구 | "채널"이 통화 건수인지 SIP leg인지 확인 필요 |
| 녹취 동시 처리 | NVMe 로컬 스풀과 중앙 스토리지 이관 구조면 가능 |
| 위험 조건 | 실시간 TTS 합성, 코덱 트랜스코딩, STT/화자분리 실시간 처리까지 통합 서버에서 수행하면 분리 필요 |

전제 조건:

- PBX 음성 코덱은 가능하면 G.711 계열로 통일하고 트랜스코딩을 최소화한다.
- TTS는 통화 중 실시간 합성이 아니라 사전 생성/캐시를 우선한다.
- 녹취는 통합 서버 로컬 NVMe에 먼저 저장한 뒤 스토리지 서버로 이관한다.
- DB는 통합 서버 내부가 아니라 별도 DB 2대에 둔다.
- 100명 동시 통화까지 요구하면 SIP/PBX 세션은 200채널 이상을 기준으로 검증한다.

## 7. 최소 서버 사양

Ubuntu Server 24.04 LTS 기준이다.

| 구분 | 최소 사양 | 권장 사양 |
|---|---|---|
| 통합 서버 | 16C/32T CPU, 64GB ECC RAM, OS NVMe RAID1 960GB, 녹취 스풀 NVMe 2TB, dual 10GbE, dual PSU | 24C/48T CPU, 128GB ECC RAM, OS NVMe RAID1 1.92TB, 녹취 스풀 NVMe 4TB |
| 백업 통합 서버 | 통합 서버와 동일 또는 CPU/RAM 80% 수준 | 본 서버와 동일 사양 권장 |
| DB 본/복제 서버 | 8C/16T CPU, 32GB ECC RAM, NVMe RAID1 1.92TB, dual 10GbE | 12~16C CPU, 64GB ECC RAM, NVMe RAID1/RAID10 |
| 스토리지 서버 | usable 80TB, RAID6/ZFS RAIDZ2, 10GbE, snapshot | usable 120~150TB, hot spare, 오프사이트 백업 |
| OS | Ubuntu Server 24.04 LTS | Ubuntu Pro 선택 가능 |

최소 사양의 핵심은 CPU보다 I/O와 네트워크다. PBX 자체는 100~200채널급을 서버급 CPU에서 처리 가능하지만, 녹취 스풀, DB 쓰기, 외부 API 지연, 장애 시 재처리가 같이 발생하므로 NVMe와 10GbE를 기본으로 잡는다.

## 8. K-CTI 솔루션 가격 산정 기준

K-CTI 가격은 장비를 제외하고 산정한다. 상담원 라이선스와 외부 솔루션 연동은 별도 항목으로 분리한다.

가격 기준은 공개된 기존 솔루션 가격을 참고해 조정한다.

- KT 콜센터 커스텀: 3년 계약 기준 좌석당 월 107,525원.
- Genesys Cloud CX: 공식 가격 기준 CX1 사용자당 월 $75, CX2 월 $115, CX3 월 $155.
- Amazon Connect: 좌석 라이선스보다 사용량 과금 구조이며 voice 분당 $0.038.

K-CTI는 클라우드 월과금이 아니라 구축형 사용권에 가깝게 제안하므로, 100석 기준 상담원 라이선스는 기존 SaaS형 CTI 1년 사용료보다 낮거나 유사한 수준으로 산정한다.

## 9. 외부 연동 범위 구분

외부 연동은 두 가지로 분리한다.

| 구분 | 구조 | 범위 |
|---|---|---|
| 콜마너 인입 연동 | K-CTI 엔진에 추가되는 기능 | 호 인입 시 고객 조회, 신규/기존 고객 분기, 상담 이력 생성, 라우팅 정책 반영 |
| 외부 상담 솔루션 연동 | 별도 앱/브릿지 개발 | 전화 수신 시 상담원이 사용하는 외부 솔루션 화면 호출, 고객정보 전달, 처리 결과 수신 |

콜마너 인입 연동은 콜 흐름 자체에 영향을 주므로 K-CTI 엔진 내부 기능으로 구현한다. 외부 상담 솔루션 연동은 상담원 PC 또는 웹 화면에서 동작하는 별도 앱/브릿지로 분리해, 외부 솔루션 변경 시 K-CTI 엔진 영향도를 낮춘다.
